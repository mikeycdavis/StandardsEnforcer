## What the repository is

A zero-dependency Node ≥18 ESM CLI (~1,600 lines over 9 modules) plus a reusable GitHub Actions
workflow. No server, no database, no HTTP surface, no background jobs. Full reference:
[`docs/architecture.md`](../../docs/architecture.md).

It decides which independent standards releases govern a repository, pins them by immutable identity,
runs their official evaluators, and refuses to let a required standard be silently absent or bypassed.
**It contains no standard** — no rule, no detector, no applicability logic, no scoring
([ADR 0001](../adr/0001-orchestrate-do-not-reimplement.md), held by
`test/authority-boundary.test.mjs`).

The governing invariant, INV-E1: *never convert an unknown, missing, unverifiable, or failed
enforcement condition into a successful compliance result.*

## Vocabulary used in this document

These are kept distinct on purpose and must not be collapsed into "not done".

| Word | Means |
|---|---|
| **failed** | Was attempted, ran, and produced a negative result |
| **falsified** | A claim was tested and shown to be untrue. Superseded, not deleted |
| **blocked** | Cannot proceed until a named external condition holds. Names its owner |
| **dormant** | Designed and not run, because the environment to run it is unavailable. An accessibility boundary, **not** a failure |
| **not run** | Nothing prevented it; it has not been done |
| **unknown** | Not established either way |
| **unsupported** | The platform or data source does not expose what would be needed |

## Where things stand

### Complete and evidenced

- **M1 — authority transport.** Given a *(repository, tag, 40-hex SHA)* identity, the enforcer
  executes the pack's own evaluator and reports its result without reinterpretation.
  Evidence: [`2026-08-09-m1-oracle.md`](../evidence/2026-08-09-m1-oracle.md).
- **M2 — contract-driven transport and the enforcement root.** The enforcer reads a pinned release's
  own `standards-adapter.json`, validates it against an executed schema, confirms the entrypoint
  resolves inside the verified checkout, and decides passing solely from the set that release
  declared. Released as `0.4.0`, breaking. Recorded as **`IMPLEMENTED — PORTFOLIO_BLOCKED`**, which is
  a truthful state: the architecture is demonstrated, upstream authorities have unresolved
  prerequisites. Evidence: [`2026-08-10-m2-acceptance.md`](../evidence/2026-08-10-m2-acceptance.md).
- **M3 — scope as a recorded decision.** Detection is evidence and decides nothing; the registry is
  held outside the governed repository and keyed by immutable platform identity; staleness is a change
  in the *kinds* of evidence, not a timer.
  Evidence: [`2026-08-09-m3-scope-registry.md`](../evidence/2026-08-09-m3-scope-registry.md).

### Falsified — preserved, not rewritten

- **M2's central mitigation does not work.** Binding a required check to the GitHub Actions app was
  M2's answer to name-spoofing. M4 established against a live repository that every workflow in a
  repository runs as that app — including one a pull request adds — so the binding is satisfied by the
  pull request's own green tick. Observed: `mergeable: MERGEABLE, mergeStateStatus: CLEAN` on a PR
  that had deleted the enforcement and replaced it with `run: echo`.
  Evidence: [`2026-08-10-m4-live-github.md`](../evidence/2026-08-10-m4-live-github.md), with raw API
  JSON preserved under [`m4-raw/`](../evidence/m4-raw/).
  The finding is recorded in `scripts/gate.mjs` at `GITHUB_ACTIONS_APP_ID`, and the code now refuses
  an Actions-only binding.

### Dormant — designed, not run, environment unavailable

- **ST-07 — validate the required-workflows remedy against a real organisation ruleset.**
  The remedy for the falsified mitigation is GitHub's `workflows` ruleset rule, which pins a
  repository, a path and a commit. `assessGate` already requires it and returns `GATE_CONFIG_INVALID`
  without one. **Nothing has confirmed it behaves as modelled on GitHub.**
  M4's own asymmetry: **the hole is proven, the patch is not.**
  - *Owner:* StandardsEnforcer
  - *Blocking condition:* required workflows are an organisation feature; no organisation is available
  - *Reopening condition:* an organisation ruleset can be created and read
  - *Currently labelled `BLOCKED` in the backlog. On the evidence it is **dormant**, not failed* — see
    Open items below.

  **Therefore, stated plainly and without softening: StandardsEnforcer has no live-validated
  authoritative GitHub Actions enforcement root.** Do not search for a more convenient mechanism
  merely to make that sentence turn green, and do not substitute a different experiment under the same
  milestone.

- **FE-09 — make `BYPASS_USED` reachable.** A defined state with settled semantics
  ([ADR 0003](../adr/0003-the-enforcement-root.md)) and no code path that can produce it.
  - *Owner:* StandardsEnforcer
  - *Blocking condition:* **unsupported** — GitHub exposes bypass events only through audit-log
    endpoints this enforcer cannot assume are available. Blocked on data, not design.
  - The state is deliberately **not faked**. `REACHABLE` in `scripts/states.mjs` records the gap and a
    test asserts it. It is the only such gap.

### Blocked on another repository

- **EngineeringStandards has no immutable release.** `VERSION` says `2.0.0`; `git tag` is empty.
  - *Owner:* **EngineeringStandards**, not this repository. Per the ownership rule, this is **not** a
    StandardsEnforcer backlog item.
  - *Blocked condition:* `refs/tags/v2.0.0` does not exist as a truthful immutable release identity
  - *Mechanical reopening condition:* `v2.0.0` exists in the authoritative EngineeringStandards remote
    **AND** dereferences to a 40-hex commit **AND** that commit is the release commit approved by
    EngineeringStandards' own release gate
  - *Consequence:* StandardsEnforcer records EngineeringStandards as **IN_SCOPE + UNRESOLVED**, held
    outside its enforcement identity contract. No synthetic triple, no special case.

### Not run

- **No live GitHub *organisation* has ever been met.** M4 exercised a live *repository*. The adapter's
  `integration_id`/`app_id` semantics for organisation-scoped rulesets remain written from documented
  responses. This is the weakest link and the prerequisite for calling anything production-ready.
- **FE-06 — the disposition of `main`.** `main` is **17 commits behind** this branch and describes a
  repository at `0.2.0`/`0.3.0` version ambiguity with M2 open. Anyone reading the default branch gets
  the earlier answer. Deliberately phrased as a decision, not a merge. **Now more urgent**; not decided
  here.

### Unscheduled by design

EP-05 carries the five gaps the README states plainly: repository discovery, a second platform
adapter, reachable bypass detection, reviewer identity beyond a configured list, and cross-pack
dependency ordering. **None is scheduled.** They exist so a future reader can tell an acknowledged gap
from an unnoticed one.
