## What

Establish whether enforcement of a release is rooted outside the changes the governed pull request
controls, and produce no verdict where it is not.

## Why

A standards check that a pull request can add, rename, or satisfy for itself is decoration. The
question is not whether a check ran but whether anything the pull request could not touch required
it.

## Notes

The pattern across this epic is three for three: every time a gate semantic was checked against
reality instead of against its documentation, the reality was weaker. A name-matched requirement is
satisfiable by the pull request; an Actions-bound requirement turned out to be satisfiable too.

Open because M4 established a defect it could not establish the fix for.
