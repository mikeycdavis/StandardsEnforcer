C-B from the [M3 reconciliation](../../evidence/2026-08-12-m3-reconciliation.md).

## What

[FE-18](FE-18.md) established what it means for **one** applicability determination to be current. It
says nothing about which determinations ought to exist — and a cell that does not exist cannot be
stale, cannot be reviewed, and cannot fail. That is the last shape of the bypass this milestone
closes: **not "declare it out of scope", but "never appear in the population".**

## The identity contract, written before the ratchet

Making the population total forces a question the enforcer had been able to avoid: *what identifies a
cell?* Until now the answer leaked in from the invocation, and FE-12 closed recording the residue in
as many words — *"`--standard` is unvalidated beyond presence; a typo and a genuinely unreviewed pack
look the same from the outcome alone."*

Harmless while cells are resolved one at a time. **Not harmless once a population is enumerated**,
because a misspelling then retires one cell and mints another with no governance event anywhere.

```text
cellKey = repoId ␀ contractId

repoId      an immutable platform identity, opaque here        (ADR 0004)
contractId  the `standard.id` the pack declares about itself   (ADR 0008)
```

Registration is **transcription**. The roster key must equal `contract.id`, a `sourceRef` records
which commit the identity was read out of, and a spelling nobody registered is refused *differently*
from a registered pack with no disposition — a typo is a configuration error, an unreviewed pack is a
governance gap.

**The tension with FE-12 is adjudicated, not overturned.** FE-12 found that reading `standard.id` out
of a pinned release broke seven seam tests, among them *a reviewed exclusion survives a malformed
adapter*: a human decided the standard does not govern this repository, and a broken contract is not
new information about that decision. So the ratchet reads the **transcribed** identity and never
opens a pack. Confirming a transcription against a resolved contract is a separate check with a
separate owner, and when it is built its failure mode must be a reported mismatch, never the erasure
of a recorded decision.

## Fails closed on seven conditions

```text
a registered repository missing from the baseline
a registered pack missing from the baseline
a baseline cell whose repository or pack no longer exists
an exclusion added or widened without the corresponding baseline edit
a malformed or missing baseline
any mechanism that silently regenerates the baseline
an empty population                                              ← found by the first real run
```

The third is the one people forget: **removal is the cheap bypass, because it looks like tidying.** An
addition gets reviewed; a deletion gets waved through. Here they are equally loud.

The fifth is why there is no "nothing to compare" path — deletion must be strictly worse than
editing, or the response to a finding is to delete the ratchet.

The sixth is why there is **no `--write`, no `--update-baseline`, no regenerate switch**, and why its
absence is asserted against the source rather than documented as discouraged. Transplanted from
`PredictionStandards/scripts/integrity.mjs`: *the first response to a red build would be to run it.*

## What is ratcheted, and what is only reported

```text
RATCHET STATE       the exclusion RULE — the glob and its reason, as configuration
REPORTING EVIDENCE  the matched-file COUNT beneath that rule
```

Ratcheting counts would re-import exactly the churn ADR 0007 refused: `vendor/**` grows by two files,
the build goes red for a reason the reviewer knows is meaningless, and the control teaches the people
it governs to stop reading it. The **negative control** pins this: same rule, same reason, four
hundred more matched files, clean run.

A widened glob is caught because the string differs. There is deliberately no containment analysis —
comparing unequal is the fail-closed direction, and a subset detector would be a second glob
semantics to get wrong.

## The finding the first run produced

**`POPULATION_EMPTY` did not exist when the first real snapshot was attempted.** Every check above
passes vacuously over zero cells, so the first run of a control built to make absence expensive
**exited zero**.

Same shape as the false green already recorded in this repository's own README — *a file under
`test/` with no tests in it counts as a passing test*. A control that holds over nothing is not a
clean result; it is the absence of one wearing a clean result's costume. Now the seventh condition,
pinned with its pair: one registered repository is enough to make the population real, after which
the ordinary findings apply again rather than being masked.

## Not in this slice

No repository discovery, no second platform adapter, no reviewer-identity expansion, no dependency
ordering, no enforcement installation. FE-07 through FE-11 remain separate obligations, and the
transcription-confirmation check above is unbuilt by decision.
