## What

Which test files constitute this repository's authoritative suite is **stated by this repository**.
It is not whatever the runner finds beneath the working directory at the moment it runs.

## Why

[ST-13](ST-13.md) measured the gap rather than inferring it. `npm test` was `node --test` with no
path argument, and on a hosted run the oracle is checked out into `.oracle` at the repository root:

| Surface | Tests reported | What the oracle contributes |
| --- | --- | --- |
| authoritative container gate | 328 | nothing — `git archive` stages this repository only |
| authoritative hosted run | 500 | the remainder |

*"The count is not a discrepancy to reconcile; it is two suites added together."*

Two failure directions, both live: **dilution**, where a hosted green covers a population this
repository does not own and did not intend to certify; and **foreign red**, where a defect in
MachineLearningStandards fails *this* repository's authoritative run with no local cause.

**Why this feature is [EP-07](EP-07.md)'s.** Its outcome is the composition of the suite — which
files the pipeline consists of — and the remedy is build machinery, `scripts/test-surface.mjs`. ST-13
argues its own placement under EP-06 (*"an assurance surface reporting more than it establishes"*)
and that argument stands on its item; the owner's disposition of 2026-09-18 reads the outcome as
composition. Both readings are recorded rather than one being erased.

## Acceptance

ST-13's five criteria, verbatim in substance:

1. The test command enumerates **only this repository's intended test surface**, and which files
   those are is stated rather than left to the working directory.
2. The oracle-backed integration tests **still execute**. A remedy that narrows the surface until
   the oracle-dependent tests fall outside it is the [FE-14](FE-14.md) defect returning by another
   route.
3. The remedy must **not hide or skip** oracle integration. A required oracle that cannot be
   resolved stays a failure.
4. Hosted and container counts may differ **only for explicitly justified environment-specific
   tests**, and the justified difference must be enumerable.
5. A **regression test proves `.oracle/test/**` cannot enter this repository's suite**. Asserting
   the current count is not that test.

## Closed 2026-09-18 — on ST-13's evidence, not on new work

All five were established on hosted run
[32875266241](https://github.com/mikeycdavis/StandardsEnforcer/actions/runs/32875266241), `head_sha`
`d87e21ef5cb43f8e163a2a931521359022c74f77`, on 2026-08-25. The mechanism is `scripts/test-surface.mjs`:
the surface is listed and passed explicitly to the runner, and an empty enumeration throws instead of
running a suite that would pass by containing nothing.

Two details from ST-13's closure that this feature carries forward as standing requirements:

- **Verification must happen where the defect lives.** Node 22 changed discovery to a glob that skips
  dot-directories, so `.oracle/test/**` is invisible on a Node 24 developer host and live on the
  pinned Node 20 runner. Verification on the host would have proved nothing.
- **The regression test does not assert a count.** It builds a sandbox with both a `.oracle/test/`
  decoy and a **non-hidden** `vendor/test/` decoy, because `.oracle` alone would pass on Node 22+ for
  the incidental reason that it is a dot-directory.

The closing date is the date this feature was written; 2026-08-25 is the date the property was
established, and it is recorded on ST-13 with its run.

## What this does not do

name, never on an aggregate count, so the contamination never touched its evidence. ST-13 says so
