## What

Three suites hardcode an absolute path to the authoritative oracle and gate every subject-touching
test on its presence:

```js
const MLS = "F:/Repos/MachineLearningStandards";                    // test/enforce.test.mjs:29
const MLS_AVAILABLE = existsSync(path.join(MLS, ".git")) && ...;    // and gate.test.mjs:28,
test("oracle · ...", { skip: !MLS_AVAILABLE && "..." }, ...)        // and scope.test.mjs:32
```

`.github/workflows/ci.yml` runs on `ubuntu-latest`, where that path cannot exist. Every identity,
adoption, oracle, gate-root and scope-integration test therefore **skips on CI, and `npm test` exits
0**.

## Why

**CI can certify this repository without exercising the authoritative integration surface at all.**
That is the same false-green shape the repository exists to refuse, sitting in the mechanism that is
supposed to detect it.

The consequence is not hypothetical: the suite's headline count is environment-dependent, and nothing
in the repository says so. A number produced on a machine with the oracle on disk travels into
acceptance records and handoff documents where it reads as a property of the code.

The invariant, stated so it does not depend on any particular count:

> **Oracle-dependent tests skipped because the authoritative repository is unavailable are not
> evidence of passing integration, and CI must not report a green authoritative suite merely because
> those tests were skipped.**

## Notes

**Found by the M3 reconciliation on 2026-08-12**, by reading the CI workflow against the test files
rather than by running anything — which is the same way [FE-13](FE-13.md) was found, and the same
finding about the suite: nothing exercises these paths adversarially.

**The fix pattern already exists in this repository.** ADR 0005 case 7b probes symlink capability
against a throwaway file, *separately* from the fixture, so only a platform that genuinely cannot
create symlinks earns a skip; a capable platform where the fixture then fails goes red. That
discipline was applied to one test in `7fa4fa4` while ~20 path-gated skips sat beside it untouched.

**This reaches past EP-01.** `gate.test.mjs` gates EP-02's evidence and `scope.test.mjs` gates
EP-03's. It is recorded here because the oracle is EP-01's, but no epic's integration evidence is
currently exercised on CI.

**What this is not:** it is not a claim that any of those tests fail. They pass locally. What is
established is that their passing is not established anywhere else.

## Acceptance property

> Unavailability of the oracle must be capable of turning the suite **red**, and must do so wherever
> the suite is claimed to be authoritative.

A fix that merely renames the constant or reads it from an environment variable satisfies nothing:
the skip is still a skip, and CI is still green. The remedy is the pairing — a probe that
distinguishes *cannot* from *did not*, plus a required-oracle mode under which absence is a failure.

## Start from the red reproduction

```text
set ENFORCER_REQUIRE_ORACLE=1
  → make the oracle unavailable
  → run the suite
  → current implementation exits 0 with tests skipped     [expected red reproduction]
```

Freeze that before designing the remedy, for the reason FE-13 gives: a guard never seen to bite is
not evidence.

**One dependency is unresolved and must not be resolved by convenience.** Whether
MachineLearningStandards is reachable from a hosted runner has not been established. If it is not,
the truthful outcome is that CI **fails explicitly** under a required-oracle flag until an oracle is
provided. Substituting the synthetic packs from `test/adapter-provenance.test.mjs` is not an
acceptable resolution: synthetic packs prove the mechanism, and only an oracle nobody in this
repository wrote proves the integration.

## Where this stands — `IN_PROGRESS`, and why not complete

Implemented in `29510e3`. The local mechanism is proven; the production failure mode is not yet
closed end to end.

```text
local mechanism proven                  ✓   test/oracle.mjs, three conditions, guard test
missing required oracle fails           ✓   exit 1, both pinned releases named
real oracle causes tests to execute     ✓   skipped 18 → 1, and that 1 is 7b
hosted CI obtains authoritative oracle  ?   unresolved deployment dependency
hosted CI executes oracle tests         ?   unresolved deployment dependency
```

**FE-14 is about eliminating the CI false green specifically.** A deliberately red hosted run is
better than the old silent green, but it is an unresolved dependency, not completion.

### The block is upstream release state, not a defect here

Probed 2026-08-12. The authoritative remote is
`https://github.com/mikeycdavis/MachineLearningStandards`. It is reachable and **private**, and
`git ls-remote --tags` returns **nothing**: the remote carries no tags at all. `v1.4.0` and `v1.5.0`
exist only in the local working copy, which is itself on branch `v1.4-candidate`.

**The authority FE-14 requires does not exist in the hosted environment yet.**

```text
MachineLearningStandards' owner must publish the authoritative releases named by
ORACLE_TAGS to the authoritative remote.

Required:
  v1.4.0 → expected release identity   (locally 6bfd0789e50196da3ff666594ff5b981b8ae5763)
  v1.5.0 → expected release identity   (locally d9cffa11df68f15da9aadc6032ca49748cad5946)

Only after those identities exist remotely can StandardsEnforcer prove hosted
oracle identity + execution.
```

The locally-resolved SHAs are recorded as *expected*, not as the answer: what the remote publishes
under those tags is the pack owner's act, and if it differs from the local copy that is a finding
rather than a discrepancy to reconcile away.

**StandardsEnforcer does not resolve this by pushing.** Minting releases in another repository so
this one's CI can go green is exactly what the M2 acceptance record refused when it declined to tag
Engineering on its behalf — and it would be worse here, because the tag would be the very identity
this suite claims to verify independently.

**Do not close FE-14 on a deliberately red hosted run that merely shows the tags are missing.** That
proves the dependency is blocked, not the acceptance property.

**One thing to fix when the dependency clears:** the workflow's
`secrets.ENFORCER_ORACLE_TOKEN || github.token` fallback. Against a private oracle, `github.token`
cannot clone across repositories, so a missing credential would surface as though the oracle itself
were invalid. Credential unavailability must be reported distinctly from release-identity failure —
the same *unknown is not absence* distinction the enforcer already draws everywhere else.

**Closing condition, and it is deliberately not "the workflow went green":**

> A real hosted run demonstrates that the oracle-dependent tests **executed** — not merely that the
> job returned success. A green run in which they skipped is the original defect, and would close
> this item on the evidence of the thing it exists to prevent.

**The hosted proof must establish authority as well as execution**, which are two claims and not one:

```text
identity    the runner resolved the intended pinned MachineLearningStandards releases
            -- every tag in ORACLE_TAGS -- from the configured ENFORCER_ORACLE_REMOTE
execution   the previously gated oracle tests ran against those releases
```

*Something cloned and tests ran* satisfies neither. It is the same authority-not-substitute principle
the local mechanism already enforces: a repository that resolves the tags is not necessarily the
repository whose releases these assertions are about, and a run that executed tests is not
necessarily a run that executed **these** tests. The guard in `oracle-required.test.mjs` checks the
first on every run; the hosted evidence has to record it, because a workflow that was reconfigured to
point somewhere convenient would still pass that guard.

## A measurement that must not be cited later

An earlier report in this work quoted a pre-change baseline of **"173 tests, 172 pass, 1 skipped"**.
**That run was contaminated** and must not be cited as a clean pre-change measurement: the worktree
it came from held another session's uncommitted work — an untracked `test/identity-cache.test.mjs`
and a modified `test/identity-provenance.test.mjs` — whose roughly nine tests are the whole of the
count discrepancy against this branch's 166.

Recorded because a discarded number is easier to cite than to remember discarding, and this one
would read as evidence that the suite shrank.
