## What

`npm test` is `node --test` with no path argument, so the runner discovers test files recursively
from the working directory. On an authoritative hosted run the oracle is checked out into `.oracle`
at the repository root, and `.oracle` is not excluded — not by `.gitignore`, not by a path argument,
not by any filter. The hosted run therefore executes **MachineLearningStandards' own test suite in
addition to this repository's**, and reports one number covering both.

Measured, not inferred:

| Surface | Tests reported | What the oracle contributes |
|---|---|---|
| authoritative container gate | 328 | nothing — `git archive` stages this repository only |
| authoritative hosted run | 500 | the remainder |

A test name present in the hosted output and absent from this repository's tree —
*"a virtualenv is recognised by structure, not by name"* — resolves to
`MachineLearningStandards/test/v11-remediations.test.mjs`. The count is not a discrepancy to
reconcile; it is two suites added together.

## Why this is EP-06's problem and not a tidiness complaint

A passing hosted count cannot currently be read as *"the StandardsEnforcer suite passed"* without
discriminating each result by test name or source file. That is an assurance surface reporting more
than it establishes, which is this epic's property exactly, sitting in the run this repository
treats as authoritative.

Two failure directions, both live:

- **Dilution.** A hosted green covers a population this repository does not own and did not intend
  to certify. The oracle's suite passing says nothing about the enforcer.
- **Foreign red.** A defect in the oracle repository fails *this* repository's authoritative run.
  The pin at [520117d](https://github.com/mikeycdavis/StandardsEnforcer/commit/520117d) makes that
  concrete: the suites now run against v1.6.0, and a red there would arrive here as a red with no
  local cause.

## Acceptance

1. This repository's test command enumerates **only this repository's intended test surface**. Which
   files that is must be stated, not left to whatever the working directory happens to contain.
2. The oracle-backed integration tests **still execute**. A remedy that narrows the surface until
   the oracle-dependent tests fall outside it is the FE-14 defect returning by another route.
3. The remedy must **not hide or skip** oracle integration. A required oracle that cannot be
   resolved stays a failure; nothing here may convert it into a skip, an exclusion, or a pass.
4. Hosted and container counts may differ **only for explicitly justified environment-specific
   tests** — the three `git archive` line-ending skips are the present example — and never because
   an entire mounted or checked-out repository was recursively discovered. The justified difference
   must be enumerable.
5. A **regression test proves `.oracle/test/**` cannot enter this repository's suite**. Asserting
   the current count is not that test: it passes for the wrong reason the moment either suite
   changes size. The test must establish the exclusion itself.

## What this item does not do

**It does not reopen [FE-14](FE-14.md), and must not be read as doing so.** FE-14 closed on the six
oracle-dependent tests being verified **by name** in hosted run
[32162621796](https://github.com/mikeycdavis/StandardsEnforcer/actions/runs/32162621796), together
with the tag identities `oracle-readiness` resolved. Name-level verification is precisely the
discrimination this item asks to be made structural, so FE-14's evidence is unaffected by the
contamination: it never rested on the aggregate count. Nothing here retroactively invalidates it.

Recorded while closing FE-14, and deliberately filed rather than fixed in that change — a closure
commit is not the place to alter what the authoritative suite runs.

## Closure

Closed 2026-08-25 on hosted run
[32875266241](https://github.com/mikeycdavis/StandardsEnforcer/actions/runs/32875266241),
`head_sha` `d87e21ef5cb43f8e163a2a931521359022c74f77`, attempt 1, conclusion `success` — the run's
`head_sha` was checked against the pull request head rather than read from a check summary, because
that summary has been observed reporting a stale head.

The mechanism is `scripts/test-surface.mjs`: `npm test` no longer runs `node --test` with no
operand. The surface is **enumerated** — `test/*.test.mjs`, listed and passed explicitly to the
runner — so what executes is stated by this repository rather than discovered from whatever the
working directory contains. An empty enumeration throws instead of running a suite that would pass
by containing nothing.

What established each acceptance criterion, on the hosted run:

1. **Node 20 executed it.** `node-version: 20`, `Acquiring 20.20.2 - x64`, `node: v20.20.2`. This
   matters because the defect is version-conditional: Node 22 changed discovery to a glob that
   skips dot-directories, so `.oracle/test/**` is invisible on a Node 24 developer host and live on
   the pinned Node 20 runner. Verification on the host would have proved nothing.
2. **The oracle was actually present**, at the root, in the exact arrangement that caused the
   contamination — `path: .oracle`, `ENFORCER_ORACLE_REPO=…/StandardsEnforcer/.oracle`,
   `ENFORCER_REQUIRE_ORACLE=1`, `ok oracle-readiness`.
3. **All six FE-14 oracle tests executed**, by name, none skipped:
   `ok 169` MachineLearningStandards under its own v1.4.0 reproduces the recorded verdict ·
   `ok 170` the enforcer's payload IS the official evaluator's output, not a recomputation ·
   `ok 171` a non-compliant target reports non-compliant, with the official numbers ·
   `ok 173` the specimen that found the false green does not pass, and no ML field is consulted ·
   `ok 262` a run that claims to be authoritative has an authoritative oracle ·
   `ok 263` the three conditions stay distinguishable.
4. **The contamination is absent by name.** The marker this item cited — *"a virtualenv is
   recognised by structure, not by name"*, resolving to MachineLearningStandards' own suite — has
   **zero** occurrences in the hosted output. The hosted total fell from the 500 recorded above to
   345, matching the container and host totals exactly. Absence by name, not a count that happens
   to agree.
5. **The only hosted skip is pre-existing and platform-inherent**: `5b · a differently-spelled path
   naming the registry's policy is not a conflict # SKIP drive-letter case folding is win32-only`.
   All three authoritative surfaces run the same 345 tests, and every skip on each is named:

   | Surface | tests / pass / fail / skip | The skips, enumerated |
   | --- | --- | --- |
   | hosted, run 32875266241 | 345 / 344 / 0 / 1 | `5b`, win32-only |
   | container, `scripts/ci.ps1` at `7ea91bd` | 345 / 341 / 0 / 4 | `5b`, plus the three `git archive` line-ending cases |
   | developer host, Windows | 345 / 319 / 0 / 26 | 22 oracle-dependent, 4 symlink (`7b`, `7d`, `7e`, `7f`) |

   The three sets are complementary rather than equal, and each difference is the environment
   rather than the surface: the container and the hosted runner both hold the oracle and both
   create symlinks, so the 26 the developer host skips resolve there; the container stages the tree
   with `git archive` and therefore carries no git metadata, so the three line-ending declarations
   cannot be read and say so. Those three are precisely the justified environment-specific
   difference **Acceptance** clause 4 names, and they are the whole of it. No new skip appeared on
   any surface, and no surface skipped anything for want of a test it should have run.

The five guards this item required ran hosted, on Node 20, where the defect lives: `ok 341`–`ok
345`. Criterion 5's regression test does not assert a count. It builds a sandbox containing both a
`.oracle/test/` decoy and a **non-hidden** `vendor/test/` decoy, and requires the runner to execute
the owned file and neither decoy — the `vendor/` case is load-bearing, because `.oracle` alone
would pass on Node 22+ for the incidental reason that it is a dot-directory.

Criterion 3 is satisfied by leaving the oracle requirement untouched: nothing here converts an
unresolvable oracle into a skip, an exclusion, or a pass, and the 22 oracle skips remain skips with
their reason attached on surfaces where no oracle is configured.

Adding `.oracle/` to `.gitignore` was considered and **deliberately excluded**. It is not required
to establish the test-surface property — the enumeration is what establishes it, and an ignore rule
would have masked the defect rather than stated the surface — and it remains a separate decision.

Consistent with *What this item does not do* above: [FE-14](FE-14.md) is not reopened. Its six
tests are verified here as still executing, which is confirmation of its evidence, not a
re-adjudication of it.
