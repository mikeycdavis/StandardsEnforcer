## What

[ST-11](ST-11.md) found one source-scanning test that became vacuous because the bytes it read were
not the bytes it was written against. This item asks the question ST-11 deliberately did not answer:
**is that one specimen, or a class?**

## The established fact, stated no wider than it was measured

> Authoritative CI may execute text whose line endings differ from the committed blob, and at least
> one source-inspection test was line-ending-sensitive enough to become vacuously green.

That is all. Specifically **not** established:

- that `.mjs` must be pinned to `text eol=lf`;
- that any other scanner is affected;
- that the line endings are a defect at all. Node does not care, and `.gitattributes` already pins
  `*.sh` for a reason that was real and named (a CRLF shebang is unparseable inside the container).

## Why the obvious remedy is not adopted yet

Pinning `*.mjs text eol=lf` repository-wide would have prevented ST-11's instance, which makes it
tempting. It is being held because it solves the scanners' *environment* rather than the scanners:
a normalised tree makes a fragile extraction work again without making it report when it stops
working. ST-11's repair — assert the extraction found something — survives a future environment that
normalisation does not anticipate. A tree-wide `.gitattributes` change also rewrites every `.mjs` in
every working copy, which is a large diff to take on evidence of one.

If the audit finds several affected scanners, a repository-level text invariant becomes earned and
can be argued on its own evidence. If ST-11 is the only one, fixing the scanner was the right
boundary and this item closes with that finding recorded.

## How

Enumerate every test that reads source (or any repository file) **as text** and derives structure
from it — `readFile` plus `indexOf`/`slice`/`split`/`match` over the result. `test/authority-boundary.test.mjs`
is the known starting point: it scans `scripts/**/*.mjs` for ADR 0001's prohibited domain vocabulary,
it is one of the oldest guards here, and it is the one whose silence would matter most.

Classify each into exactly one of:

```text
1. line-ending agnostic already          → no action
2. sensitive, but fails loudly           → no action; record why it is loud
3. sensitive, and can succeed vacuously  → a live assurance defect
```

Only class 3 is a defect. For each class-3 finding, the ST-11 pattern is the remedy: normalise,
locate, **assert located**, assert the region is the intended one, then assert.

A scanner should be classified by *execution*, not by reading it — feed it CRLF input and observe.
Reading ST-11's guard did not reveal the defect; running it against archived bytes did.

## Acceptance

- Every source-reading test in the suite is enumerated and classified, with the classification
  method recorded per test rather than asserted.
- Every class-3 finding is either repaired to the ST-11 pattern or has a recorded reason it is not.
- The `.gitattributes` question is answered **from the resulting count**, in either direction, and
  the answer is written down with its evidence — including the answer "no change".
- No scanner is repaired by rewording the source it scans.
