## What

Oracle-dependent evidence in this repository has two halves that consume the oracle in two different
senses: the **authority** (the evaluator that is run) and the **subject** (the repository it is run
against). This feature owns the property, stated in ST-14's own words:

> Oracle-dependent evidence must identify immutable Git objects whose bytes are the bytes consumed.
> A mutable host working tree may be a transport for the object database, but must not itself be
> the authority.

## Why

[ST-14](ST-14.md) audited both halves rather than assuming either. The authority half was already
object-addressed end to end. The subject half was not: `test/enforce.test.mjs` handed the oracle's
working-tree root in as the governed repository, so the bytes consumed were whatever the host
checkout happened to hold. This was observed, not hypothetical — during the 2026-08-16 audit the
oracle host tree moved from a dirty `27d4b61` to a clean `7826f24` while CI had it mounted.

`read_only: true` on the bind establishes that the container cannot write the oracle. It establishes
nothing about the host writing it concurrently. Those are different integrity directions, and only
the first was covered.

This is [EP-06](EP-06.md)'s property: a result that reports more than it establishes. A verdict that
does not say which bytes it was a verdict about is that failure in a quieter form.

## Acceptance

Drawn from ST-14's own five criteria, not composed:

1. **Every oracle-dependent assertion states which bytes it consumed**, for the subject as well as
   the authority.
2. **Where the subject is the oracle repository, it is materialised at a named commit** by the same
   verified route the authority already uses, not read from `ORACLE_REPO` in place.
3. **A regression test establishes the exclusion**: no oracle-dependent assertion that consumes the
   subject's bytes may take `ORACLE_REPO` as a target path directly. Asserting today's verdict is
   not that test.
4. **The recorded evidence names repository, tag and peeled commit SHA** for both halves. A SHA
   appearing somewhere in the output does not satisfy this.
5. **The oracle integration still executes.** A remedy that narrows the surface until the
   oracle-dependent tests fall outside it is the [FE-14](FE-14.md) defect returning by another route.
