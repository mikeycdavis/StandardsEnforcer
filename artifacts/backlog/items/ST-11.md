## What

The structural half of `test/adapter-policy-binding.test.mjs` — *the evaluator seam names no policy
filename* — was merged in PR #2 (`bfb30c4`) and had **never executed a single assertion**, in any
environment, authoritative container CI included.

```js
const src  = await readFile(new URL("../scripts/enforce.mjs", import.meta.url), "utf8");
const seam = src.slice(src.indexOf("export function runOfficialEvaluator"));
const body = seam.slice(0, seam.indexOf("\n}\n") + 1);   // ← -1 + 1 = 0
assert.equal(body.includes("POLICY_FILE"), false);        // ← asserts about ""
```

`core.autocrlf=true` on the authoring machine, and `.mjs` carries no `text eol=lf` attribute in
`.gitattributes`. The working tree carries CRLF, and — decisively — so does the `git archive` the CI
image is built from. The LF delimiter is absent, `indexOf` returns `-1`, and both assertions run
against the empty string, which contains nothing and therefore satisfies every `includes(…) === false`
put to it.

Measured rather than deduced. Against an archived `main`: `body.length` **0**.

## Why this is ST-08's shape, one level up

ST-08 established that a control which skips is not a control that held. This is the same failure
with the skip removed: nothing skipped, nothing was reported, and the test read as a pass. It is
worse in one respect — a skip is at least visible in the output, whereas a vacuous assertion is
indistinguishable from a satisfied one.

It also sat inside the commit that claimed the property was *"asserted structurally"*, and that claim
propagated into PR #2's body, its post-merge correction, and [FE-21](FE-21.md)'s acceptance list.

**What was and was not affected.** The mechanism itself was always correct, and the *behavioural*
half of the same file was always live — PR #2's policy threading is real and remains proven. What
failed was the claimed second assurance layer, not the thing it was claiming about. Falsified in both
directions against the same reconstructed defect (`{policy}` bound from `path.join(target,
POLICY_FILE)`):

| Guard | Failures |
|---|---|
| as shipped in PR #2 | **2** — both behavioural; the structural assertion stayed silent |
| repaired | **3** — the structural assertion now catches it |

## The remedy, and the ordering it fixes

Not "normalise the line endings" alone. Normalisation removes the instance; the *class* is an
extraction that can match nothing and hand its assertions an empty search space. So the pattern is
fixed, in this order, and each step is itself asserted:

```text
source normalisation
→ locate the function boundary
→ ASSERT the boundary was actually found
→ ASSERT the extracted region identifies the intended seam
→ strip comments, and ASSERT stripping left code and removed prose
→ only then, the structural assertions
```

A later source-layout change under a different delimiter therefore fails saying so, instead of
recreating the same vacuous green.

**Comment stripping is part of the repair, not a convenience.** The seam's comments discuss the
reconstruction the guard forbids — they must, to explain why — and a blunt substring scan cannot tell
an identifier from a word about one. The rejected alternative was rewording the prose, which leaves
the guard exactly as blunt and adds an invisible rule: *do not say this word here*. `stripComments`
makes the guard's subject the mechanism instead, and carries its own tests
(`test/source-scan.test.mjs`) because a stripper that ate code would manufacture the same false green
one layer further down.

## Acceptance

- The repaired guard fails on a reconstructed `{policy}` binding; the shipped one did not. Both
  measured, on identical input.
- The CRLF defect is reproduced as a test case, so a refactor cannot reintroduce it unnoticed.
- `stripComments` is asserted in both failure directions: removing code, and leaving prose.
- The suite is green on unmodified source, and authoritative container CI passes on the pushed SHA.
- The durable claims that said the structural assertion was live are corrected by appended
  supersession, not by rewriting the original narrative.

## What this does NOT establish

Whether any **other** source-scanning test in this suite shares either defect. Not audited here, and
deliberately not assumed either way — see [ST-12](ST-12.md). In particular this item makes **no**
claim that `.mjs` should be pinned to LF in `.gitattributes`; that remedy is not earned by one
specimen, and a blanket normalisation would be fixing the scanners' environment rather than the
scanners.
