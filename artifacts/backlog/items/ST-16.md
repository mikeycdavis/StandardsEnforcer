## What

[ST-15](ST-15.md) shut one shape. This story closes the rest of the same hole.

> **Acceptance property.** Any assurance verdict derived from an empty subject must fail, whatever
> shape derived it — independent of whether an accumulator was built.

## Why

ST-15's mechanism is real and its falsifier is red on `main`. But its discriminator recognises
exactly one shape: *an array declared empty, pushed to, then asserted empty* — an accumulator over
an iteration. That is what "derives a verdict from a collection" was operationalised as, and it is
narrower than the property [EP-06](EP-06.md) claims.

Measured on `main@3c02014`, with ST-15's mechanism present and its own probe correctly red. Three
further tests were added to the authoritative surface, each with an empty subject and a passing
verdict, none of them building an accumulator:

```js
// 1 · derived, not accumulated
const offenders = files.filter((f) => f.includes("FORBIDDEN"));
assert.deepEqual(offenders, []);

// 2 · asserted inside the iteration, so nothing survives it to inspect
for (const f of files) assert.ok(!f.includes("FORBIDDEN"), `${f} is malformed`);

// 3 · a predicate that is vacuously true on an empty subject
assert.ok(files.every((f) => !f.includes("FORBIDDEN")));
```

```
surface 38 | probes enumerated: 3
393 tests, 363 pass, 0 fail, 30 skipped
✔ probe-every · every source file is well formed
✔ probe-filter · no source file contains a forbidden marker
✔ probe-inloop · every source file is well formed
```

All three were enumerated by [ST-13](ST-13.md)'s surface, all three executed, and nothing objected
to any of them. **The guarantee EP-06 states is therefore not yet established** — only the
accumulator route to violating it is closed.

Shape 2 deserves particular note: it has no collection-valued verdict at all. A discriminator that
looks for a verdict *about* a collection cannot see it, because the verdict is about each element
and there were no elements. Any mechanism that closes this story has to reason about the subject
being iterated, not only about the value being asserted.

## Acceptance

Red-first, in this order. Each step evidenced by execution, not by reading.

1. **The three falsifiers exist first**, as newly enumerated tests: an empty subject with a
   `filter`/`map`-derived verdict; an empty subject with assertions only inside the iteration; an
   empty subject with an `every`/`some` predicate.
2. **Prove all three currently pass** against the base this work starts from. A falsifier never
   observed passing has not established the defect. (Observed above on `3c02014`; re-observe against
   the actual base, since that measurement will be stale by then.)
3. **Implement a standing mechanism over the authoritative test surface** — subject `testFiles(ROOT)`
   — that rejects any assurance verdict derived from an empty subject, **independent of accumulator
   shape**. All three probes must go red.
4. **Legitimate existing tests stay green.** The full surface passes with the mechanism in place. A
   mechanism that reddens honest guards has replaced one false verdict with another, and this
   story's discriminator is broader than ST-15's, so the risk of that is higher, not lower.
5. **The mechanism proves its own liveness**, as [ST-11](ST-11.md) requires of any structural guard:
   shown to fire on a planted violation and to stay silent on the remedy. ST-15's mechanism failed
   this on its first attempt — its specimens were string data, invisible to a scanner that stripped
   comments but not string bodies — so verify against a real file, not only a string.

## Explicitly not a solution

- **Extending ST-15's accumulator list with more shapes.** An enumeration of known spellings loses
  to the next spelling; this is the alias-list weakness that [ST-14](ST-14.md) had to replace with
  derivation, one level up.
- **Requiring every test to assert a non-empty subject by convention.** That is the prose rule
  ST-15 exists to have replaced.
- **Test counts, coverage thresholds, or naming conventions.** Ruled out for ST-15 and ruled out
  here for the same reason: each is fully satisfiable while all three probes above still pass.

## Progress

**2026-08-28, round one** ([evidence](../../evidence/2026-08-28-subject-liveness.md), merged as
`61e8bb7`). The mechanism landed and all three probes went red. Fourteen attack shapes: twelve
rejected, **two escaped** — a ternary and a `.join(",")` verdict — so the story stayed open.

**2026-08-28, round two** ([evidence](../../evidence/2026-08-28-subject-liveness-round-two.md)).
Both escapes closed, and the reason they escaped turned out to be structural rather than two missing
rules: `consumptions()` enumerated the **sinks** a derived collection could drain into, so it failed
open on every sink it did not know. The fix inverts the default — `assertion-shape.mjs` enumerates
the assertions that *refute* emptiness, and anything unrecognised is flagged. Not knowing is no
longer a pass.

Nine further adversarial rounds, 178 shapes. **No round found zero escapes**; the counts were
7, 8, 6, 2, 3, 4, 4, 2, 1 against the mechanism as it stood when each round began. Nine defects were
found in the mechanism itself, seven of which flagged an honest test. Five more genuine
under-proofs were found in the existing suite and each strengthened by one line.

**2026-08-28, round three** ([evidence](../../evidence/2026-08-28-verdict-language-closure.md)). The
premise itself was made checkable. Round two's control asked whether each surface file imports
`node:assert`, which admits a file that imports it *and* reaches its verdict elsewhere; three such
files now sit in `test/fixtures/subject-liveness/unsupported/`, each passing that control and
escaping the liveness rules.

The replacement is a closure argument rather than a list. Every call has a root identifier, and it is
bound by an import, bound in the file, a language global, or free — and only the fourth is unreadable.
`test-support/verdict-language.mjs` enumerates the first three and reports the rest, so an unreadable
verdict form makes the file **UNSUPPORTED**, which is an offender and never a skip. Measured: 36 of 36
files supported, zero free callees, zero bare-specifier imports. The admitted assertion vocabulary
(ten forms, 1,025 calls) is stated and checked against the surface in both directions, and every
admitted form is proved not to be a fail-open sink.

Resolving imported helpers turned up a defect in `stripComments`: a `/` inside a regex character class
ended the literal early and blanked live code in three production modules, invisible to every scanner
here. Fixed; no test outcome changed.

**Two further rounds.** Round eleven found ten escapes of twenty and does **not** count, because the
mechanism was modified during it — its faults were `assertingHelpers` enumerating declaration
syntaxes, and `assert` escaping into a value position, both fixed by inverting rather than extending.
Round twelve, run against a mechanism it did not modify, found **six escapes of twenty**.

### Round four — data-flow attribution

Evidence: [`2026-08-29-dataflow-attribution.md`](../../evidence/2026-08-29-dataflow-attribution.md).

**Round twelve's record was wrong about one of its six.** Each specimen was measured before anything
changed, and they were three faults rather than two: four attribution, one consumption
(`foreach-byref` — `blockAt` returns `check);`, so a fallback keyed on an empty body could never
fire), and one **false proof of liveness** (`symbol-iterator` — `staticallyNonEmpty` counts an object
literal's own members as proof, which is sound for an array literal and unsound for an object whose
`Symbol.iterator` yields from somewhere else).

**Five of six closed**, and are now regression specimens in `caught/`. Attribution became a two-edge
data-flow model — containment credits every containing declaration, pattern bindings carry the extent
of their initialiser, and a call is a flow edge only when the callee HANDS BACK a function, which is
what keeps `const rows = statesTable()` from being promoted. `optional-subject` closed by admitting
`?.` in the subject grammar; the repository's own evidence decided that, since six other rules in the
same mechanism already read it and the surface writes it in 7 of 36 files.

`symbol-iterator` is left open deliberately: closing it changes what counts as evidence of liveness,
and `Object.entries({ ... })` is a legitimate case where the member count IS the proof.

**Round fourteen, run against a mechanism it did not modify, found eight escapes of twenty.** Seven
are the next hop after the one just closed — a plain re-binding (`const chk = mid`, a ternary, `??=`,
a spread, `.bind()`, `Map.get()`, an argument called through its parameter). The eighth is a subject
shape (`await`).

**Still open on nine shapes**, all in `test/fixtures/subject-liveness/escapes/` with `KNOWN_ESCAPES`
checked against the directory both ways.

The list grew from one to nine because the measurement reached further, not because the gap opened —
and this was verified rather than asserted: round fourteen was run against the previous mechanism too
and escaped **11** there against **8** here, with no shape that was caught before escaping now.

**The close condition is unchanged and unmet:** an adversarial round that finds nothing, run against
a mechanism it did not modify. Fourteen rounds have been run and none has delivered one.

### Round five — the aliasing family, closed by inversion

Evidence: [`2026-08-29-reaching-definitions.md`](../../evidence/2026-08-29-reaching-definitions.md).
Scope decision by the owner, 2026-08-29: **ST-16 carries the data-flow gap** rather than handing it to
a successor, because the aliasing escapes violate this story's own standing guarantee.

**All seven aliasing shapes closed**, and by inverting the flow question rather than adding an edge
per hop: *an expression carries a checker unless every mention of a carrier is a call whose result is
data.* The set of ways a value can travel is open; the set of ways it stops is closed and has one
member. Two bindings the scan could not see at all were added around it — logical assignment (`??=`)
and a parameter that receives a carrier at a call site.

**A regression the sweep caught.** Unifying the edges dropped `class V { check(f) { assert.ok(f); } }`
reached through `const v = new V()`, caught for eleven rounds. Construction is not a call whose result
is data — it wraps the checker rather than stopping it. Found by re-running all nine earlier corpora,
not by reasoning.

**Round sixteen, run against an unchanged mechanism, found three of twenty — so the owner's clean-round
gate is NOT met and this story does not close.** Only one of the three (`member-assign.mjs`, `o.c = chk`)
is in the flow family; the others are consumption grammar and subject grammar.

**Five escapes remain, and they are four different mechanisms** — flow, consumption grammar, subject
grammar, and what counts as evidence of liveness. That is a change in kind from round twelve, where
six escapes were one fault, and it is the most useful thing this round establishes: **the flow gap is
no longer the dominant one.**

Both self-liveness guards were re-demonstrated: stripping this file's liveness assertions fails ST-16's
own scan and ST-15's accumulator guard. One qualification recorded rather than glossed — ST-15 is
satisfied by *any* liveness assertion in a file, so it fires only when none is left (eight strips,
against ST-16's one). Its independent catch is real but coarser.

### Round six — three residuals closed, and a change in what the residue is

Evidence: [`2026-08-29-three-residuals.md`](../../evidence/2026-08-29-three-residuals.md).

Round sixteen's three closed, as three separate faults: `member-assign` (member assignment binds, by
last segment), `proto-call` (a borrowed-iteration rule for `call`/`apply`), `concat-literal` (a subject
may begin with an array-literal receiver, with `for (const x of [1, 2])` asserted as a control).

**Round eighteen, run against an unchanged mechanism, found twelve of twenty** — the highest any round
has produced. It escaped 15 against the previous mechanism with no regressions, so this is a harder
corpus rather than a worse mechanism. **The number is not the finding; the composition is.**

| Family | Count |
| --- | --- |
| Flow — container mutation, computed key, destructuring assignment, factory returning an object | 5 |
| Subject grammar — `(files)`, `(0, files)`, nested calls, `await o.load()` | 4 |
| Consumption grammar — `Reflect.apply`, `Array.from(files, chk)`, borrowed `every` | 3 |

Rounds two, eleven, twelve and fourteen each had a **dominant** fault closed by inverting a default.
**Round eighteen has none.** `for (const f of (files))` is ordinary JavaScript that a parser handles
for nothing and a regex subject grammar cannot see; `s.add(chk)` is a mutation, and this analysis
follows bindings. The limit reached is the reading mechanism itself.

**A scope question for the owner, recorded rather than acted on.** Closing this residue means
extending three grammars in step, which is not a smaller job than parsing the source, and it does not
converge — ordinary JavaScript keeps producing shapes a regular expression cannot express. Whether
ST-16 moves to a real parser is a decision worth taking deliberately.

**The close condition is unchanged and unmet:** an adversarial round that finds nothing, run against a
mechanism it did not modify. Eighteen rounds have been run and none has delivered one.

### Round seven — the parse tree, and the round that found nothing

Evidence: [`2026-09-04-rounds-nineteen-to-twenty-four.md`](../../evidence/2026-09-04-rounds-nineteen-to-twenty-four.md).
Decision: [ADR 0010](../../adr/0010-the-parser-dependency-and-what-it-cost.md).

The scope question round six recorded was taken: this repository now has one dependency, acorn
8.18.0, pinned exactly with a committed integrity-locked lockfile and `npm ci` in both CI
environments. The ADR is explicit that the guarantee replacing "there is no install" is **weaker**
than the one it replaces, and says so rather than claiming equivalence.

Three of this file's four grammars were replaced; the ASSERTION grammar was deliberately kept,
because it reads a closed vocabulary checked against the surface in both directions and is built on
an inversion that fails closed — the structure the other three lacked.

**All fourteen recorded escapes are closed**, and most of them by the tree rather than by rules
written for them: `(files)` is not a node acorn produces, a `SequenceExpression`'s value is its last
expression, `await` is one `.argument` away, and five flow spellings became one question asked of a
node. `symbol-iterator` and `await-subject` — both previously recorded as out of scope for the flow
work, each needing its own mechanism — were resolved by those bounded semantics, not by a rule aimed
at either.

**Six rounds, 120 shapes, each run against a mechanism it had not yet modified:**

| Round | Escapes | What it found |
| --- | --- | --- |
| nineteen | 5 / 20 | parameter defaults and static container writers; `[files].flat()` as a false liveness proof; a length-gated recursion |
| twenty | 2 / 20 | `.at(0)` as a presence shape; an asserting `sort` comparator |
| twenty-one | 1 / 20 | a bare `switch (files.length)` whose empty case is the pass |
| twenty-two | 4 / 20 | an asserting callback inside `some`/`find`/`reduceRight`; an iterator handle advanced outside the loop test |
| twenty-three | 4 / 20 | a string-keyed method call; a detached method; an index destructure through an object pattern; a getter-returned derivation |
| **twenty-four** | **0 / 20** | **nothing** |

**The close condition is met.** Round twenty-four is twenty fresh shapes run against a mechanism
nothing touched between writing them and running them, and it found zero. No specimen caught in any
earlier round escapes now — verified by re-running all 343 `caught/` specimens after every change.

Three faults are worth separating because a parser does not fix them by itself: `[files].flat()` is
the `symbol-iterator` fault reached through flattening; the `some`/`find` exemption was about the
RESULT and had been applied to the ITERATION; and a string key is unreadable in blanked source, where
the fail-closed reading is that it could be `forEach`.

Two findings that were not escapes are recorded in the evidence rather than absorbed: `Object.groupBy`
was caught while naming `Object` as the collection nobody proved non-empty — a right answer for a
wrong reason — and a text-proximity heuristic (`mentionedInAssertion`, a search within 160 characters
of a `throw`) flagged two honest bindings in this story's own test. Both fixed.

**`escapes/` is empty, and the test asserts that case explicitly** rather than by filtering an empty
list, which would pass while examining no specimen — ST-16's own defect, reached inside ST-16's
residue check. An empty directory claims no *known* escape remains; it is not a claim that none
exists, and it is the starting position for round twenty-five.

## Notes

**Scope.** This repository's own assurance surface, per EP-06's boundary — not a guarantee offered
to governed repositories.

**Do not close EP-06 when this closes.** Evaluate the parent at the parent level afterwards, as on
2026-08-27 and again on 2026-08-28, when neither a full child count nor a single shut falsifier
established it. The reasonable expectation is that this story narrows the gap rather than closing
it, and the honest close condition for EP-06 is a falsification attempt that fails to find a fourth
shape — not the absence of one having been tried.
