C-D from the [M3 reconciliation](../../evidence/2026-08-12-m3-reconciliation.md), built **after**
[FE-19](FE-19.md) and deliberately not beside it: the ratchet defines what the population is allowed
to be, and the matrix reports that population. Built the other way round, a newly discovered
repository or pack could appear or disappear without a governance event.

## What

```bash
node scripts/portfolio.mjs --scope-registry=<file> --baseline=<file> [--repos-root=<dir>] \
                           [--as-of=YYYY-MM-DD] [--require-reviewed] [--json]
```

Two questions, one run, and they are not the same question:

```text
the ratchet   did the governed population change without a governance event?
the matrix    what does the population currently say?
```

The exit code answers the first, and the report says so on every run. A ratchet violation fails the
run without shrinking the table — **the only way to see the portfolio must not be to have already
satisfied the control.**

## Every flag either widens the population or makes the result stricter

There is no `--only-signalled`, no `--hide-unknown`, no `--summary-only`, no `--limit`. **Any option
that reduces the cell count without reducing the population is the back door this milestone was built
to close**, and its absence is asserted against the source rather than intended.

`--repos-root` locates working copies, and locating one can only make a cell resolve *further* —
never pass, because an unobservable surface is `undetermined` and `undetermined` is review-required.
`--require-reviewed` is the shape a flag is allowed to have: strictly stricter.

## Two refusals worth stating

**It does not evaluate.** An in-scope cell means a human decided the standard governs the repository;
whether that repository satisfies the standard is a question for the evaluator seam, one target at a
time. So an in-scope cell carries `evaluated: false` and **no state at all** — no member of `STATE`
means *"governed, and not evaluated here"*, and inventing one to fill the column would put a word in
the vocabulary for the sake of a table. `REACHABLE`'s gap stays exactly `["BYPASS_USED"]`.

**An unobservable repository is review-required, never a pass.** Content cannot be observed without a
working copy, and ADR 0007 makes tracked content the freshness authority. The paired arm keeps that
from being vacuous: an observed repository whose surface still matches resolves `out-of-scope`.

## The first matrix, and it is worse than the plan predicted

The plan expected *~400 cells, nearly all `SCOPE_REVIEW_REQUIRED`*. The truth is smaller and nothing
is hidden:

```text
Portfolio: 0 cells — 0 registered repositories × 4 registered packs
Ratchet:   POPULATION_EMPTY
exit=4
```

Four hundred unreviewed cells would be a portfolio entered and not reviewed. This is a portfolio
**not entered**. Two findings behind it, both recorded rather than engineered around:

- The repository axis cannot be populated without immutable platform identities, which only the
  platform issues. Directory name, root-commit SHA and remote URL were each considered and refused.
  Obtaining real ones is repository discovery — a separate obligation.
- **Five of the nine packs in this portfolio declare no contract identity at all** and are therefore
  unregistrable, recorded as such rather than omitted: a pack missing from the matrix and a pack
  missing from the world must not look the same.

Full account in
[`2026-08-13-portfolio-first-matrix.md`](../../evidence/2026-08-13-portfolio-first-matrix.md), with
the raw run preserved beside it.

## Divergence from the plan, recorded

The plan sketched `scripts/scope.mjs status` and an `enforce.mjs portfolio` subcommand. The CLI is
`scripts/portfolio.mjs` instead: `enforce.mjs`'s argument contract requires `--standards/--tag/--sha`
for a single target, and M1's invocation had to stay byte-identical. Nothing about the semantics
moved.
