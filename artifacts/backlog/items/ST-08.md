## What

The invariant to establish:

> When authoritative container CI declares symlink capability required, inability to exercise the
> symlink provenance tests is a test failure, not a skip.

Today the container exercises cases 7b, 7d, 7e and 7f because it happens to run on Linux with the
privilege to create symlinks. Nothing asserts that. `ci/checks.sh` reads the skip count for the
report and says so explicitly — *"Counts are for the report only. The verdict is the exit code"* —
which is the right principle and leaves this uncovered.

## Why

This is the defect the entrypoint-containment finding was made of, one step removed.

Case 7b was correct, committed, and had **never executed**: it skipped on the Windows workstation
for want of privilege, and hosted Actions were not running. A control with a correct assertion that
is never evaluated is indistinguishable from a control that holds — until something runs it. The
containerised pipeline ran it, and it failed immediately.

The remedy fixed the escape. It did not make the *exercising* of that case a property the pipeline
asserts. If symlink creation ever became unavailable inside the container — a rootless runtime, a
hardened daemon, a filesystem without symlink support — those four cases would skip and the
pipeline would report green, with the two containment escapes silently unguarded again.

`ENFORCER_REQUIRE_ORACLE=1` is the same shape of problem already solved for a different capability.
This is that pattern applied to the one it does not cover.

## Notes

**Not a generic zero-skip rule.** Platform-conditioned tests are legitimate, and case 7b skipping on
a Windows workstation is the correct report there — the skip message is deliberately worded so the
case reads as NOT exercised rather than as passing. What is being asserted is narrower: *this*
environment claims symlink capability as part of the authority it asserts.

Minimal shape, mirroring `test/oracle-required.test.mjs` rather than inventing a mechanism:

```text
ENFORCER_REQUIRE_SYMLINKS=1   set in compose.ci.yml and .github/workflows/ci.yml
        ↓
capability-required.test.mjs
        ↓
symlinksAvailable() === false  → red, with the reason named
symlinksAvailable() === true   → passes; the provenance cases execute normally
```

Both arms tested, exactly as the oracle requirement is:

```text
require=1 + capability unavailable  → fail
require=1 + capability available    → pass
```

The verdict stays driven by a named test. No shell inspects TAP counts, and no count decides
whether CI passed.

**This supersedes a note in [ST-05](./ST-05.md).** That item recorded case 7b as skipped and
concluded *"Not tracked as an item: it needs a machine, not a decision."* The machine now exists —
it is the CI container — and running it produced a decision worth tracking.

**Parentage.** [EP-06](./EP-06.md) — this repository's own assurance surfaces must establish what
they report. This is that property exactly, and EP-06's own justification table already rejects
EP-01 for it: the oracle being EP-01's would make EP-01 *"the accidental parent of every failure
that touches enforcement"*.

**Why not a child of [FE-14](./FE-14.md).** FE-14 is the same *shape* — a skip standing in for a
pass — and is the direct precedent for the mechanism. But FE-14 is scoped by name to the oracle,
and the capability here is different, as is the remedy's trigger. Filed as a sibling under the
shared epic so neither has to be widened to accommodate the other.
