## What

Keep this repository's own release identity honest: `VERSION` and `package.json` naming one thing,
`SCHEMA_VERSION` travelling independently, and a stated pre-1.0 rule for where breaking changes land.

## Why

Phase 3 exposed the ambiguity rather than resolving it — `VERSION` said `0.2.0` while `package.json`
said `0.3.0`, and nothing decided which was the release. A tool that reports other repositories'
version drift has no standing to carry its own.

## Notes

The three versions are documented as travelling independently, with a test asserting only the two
that genuinely share a lifecycle. Writing a test that equates all three would encode a coincidence as
a rule.

## Closure — 2026-08-23

EP-04 closes because the repository now **executably establishes all three parts** of its
release-lineage contract, not because its children are COMPLETE. The guarantee was assessed
against its own stated property; child arithmetic was deliberately not the test.

| Clause of the guarantee | Where it is established |
| --- | --- |
| `VERSION` and `package.json` name one thing | `test/release.test.mjs:28` — asserts equality; both read `0.6.0` |
| `SCHEMA_VERSION` travels independently | `test/release.test.mjs:49` — asserts it *is* a version and **deliberately omits** equality, per this item's Notes. Currently `0.5.0` against a `0.6.0` release |
| A stated pre-1.0 breaking-change rule | `test/release.test.mjs:43` — asserts `CHANGELOG.md` states both *"while below 1.0.0"* and *"MAY contain breaking public-contract changes"* |

All five assertions in `test/release.test.mjs` pass at `520117d`: 5 passed, 0 failed, **0 skipped**.

The 0.5.0 → 0.6.0 release strengthened rather than weakened the case: the pair stayed in
agreement across a version bump while `SCHEMA_VERSION` moved separately, which is the contract
behaving rather than merely holding still.

### Two qualifications, carried deliberately

- **The pre-1.0 rule is guarded as a *declared policy*, not mechanically checked against every
  historical version transition.** The test asserts the changelog states the rule; nothing
  verifies that past minor bumps actually carried the breaking changes the rule permits. That is
  a weaker guarantee than enforcement, and it is the guarantee this item claimed.
- **Hosted verification, corrected.** An earlier reading of this closure recorded the evidence as
  local-execution only, because `main@2b88466` had no executed hosted run under the established
  billing/no-runner condition — jobs were created with no runner assigned and zero steps. That
  statement was true of `2b88466` and remains true of it, but `2b88466` is no longer the head.
  At `520117d` the hosted pipeline **executed and passed** (run `32606582346`, 26s), as it did
  for the two commits before it. The qualification is therefore historical, not current.

Neither qualification prevents closure.

Not asserted here: that the release lineage is *correct*, only that its identity is honest and
guarded. Nothing about which line becomes authoritative is settled by this item.
