## What

Assess whether something outside the governed pull request's control requires the standards check on
the governed branch, producing `GATE_MISSING` or `GATE_CONFIG_INVALID` where it does not.

## Why

The presence of a workflow file in a repository is evidence that a file exists. It is not evidence
that anything requires the check to pass.

## Notes

This milestone produced the spoofable-check finding, which was not in the brief — it came out of
asking what a pull request could actually do rather than what the configuration appeared to say. A
requirement matched by name alone is satisfiable by the pull request emitting that name.

The mitigation adopted here was to require an app binding on the required check. M4 later established
that this mitigation is correct in form and empty in substance — see [[FE-04]].

Every gate semantic is asserted against an injected platform, so the second platform adapter changes
none of them. That was the right boundary for portability and, as M4 found, the wrong one for
confidence.
