## What

Found by an evidence sweep on 2026-08-13, not by a reader hitting it — which is the part worth
noting, because the README is the first thing a new reader or agent trusts.

`README.md` documented the **pre-0.4.0** state model:

```text
claimed                                        actual
COMPLIANT                    exit 0            no such state — removed in 0.4.0
COMPLIANT_WITH_EXCEPTIONS    exit 0            no such state
NON_COMPLIANT                exit 1            no such state
NOT_EVALUATED                exit 2            no such state
BLOCKED_BY_INVARIANT         exit 3            no such state
ENFORCEMENT_ERROR            exit 2            exit 4
(absent)                                       EVALUATED, with `passing` beside it
```

## Why this is not documentation debt

**It contradicts one of the project's two central architectural decisions.**
[ADR 0001](../../adr/0001-orchestrate-do-not-reimplement.md) says the enforcer must not know what a
pack's verdict *means*. The 0.4.0 rewrite removed those five pack-native statuses precisely because
mapping `NOT_EVALUATED` to `2` and `BLOCKED_BY_INVARIANT` to `3` kept that meaning in this repository
in encoded form. Moving the strings elsewhere would have been cosmetic; the semantics had to go.

A README that still lists them tells a reader the enforcer interprets verdicts — the exact belief the
rewrite exists to make impossible. And the wrong exit for `ENFORCEMENT_ERROR` is actionable
misinformation: a caller wiring a gate on `2` would treat a failure to establish enforcement as
something other than what it is.

**No code was changed.** The code was correct throughout; only its description was not.

## Where this was found, and why it was still live here

Discovered and remedied on `reconciliation/m3-integration` as `fe5d7d7`, 2026-08-13. That line never
became authoritative, so the defect went on shipping on `main` for three days after it was fixed
somewhere else — which is itself the argument for the read-only assessment that surfaced it. See
[2026-08-16-integration-line-assessment.md](../../evidence/2026-08-16-integration-line-assessment.md).

**Reconstructed, not cherry-picked, and that was a finding rather than a preference.** `fe5d7d7` is
not isolated to this item. It also carries a broadening of [FE-06](FE-06.md) — since superseded by
FE-06's own Decision 3 — and that line's backlog tracker at *"14 of 22, 64%"*, which is a different
backlog from this one's 32 items. Importing the commit would have dragged both across.

Two things in its README hunk were also **deliberately left behind**, and both would have introduced
a fresh false claim while fixing an old one:

| Left behind | Why |
| --- | --- |
| *"A declared pass is not enough on its own"* — the FE-16 property | FE-16's remedy is not on this line. `scripts/enforce.mjs` here has no exit-contradiction check, so documenting it would advertise a capability `main` does not have — the mirror image of this very defect |
| *"`artifacts/backlog/README.md` is generated, never hand-edited"* | False since [ST-10](ST-10.md). That tracker is written by hand and **checked** by `scripts/backlog.mjs`; restoring the generated claim would reinstate exactly what ST-10 removed |

Findings 3 (ADRs 0005 and 0006 unlisted) needed nothing: both were listed on `main` independently.

## A guard, where the original said there was none

The 2026-08-13 record ended: *"No test protects this. A guard that asserted the README's state table
against `STATE` is conceivable and is not built."*

It is now. `test/front-door.test.mjs` derives the expectation from
[`scripts/states.mjs`](../../../scripts/states.mjs) — the vocabulary, `EXIT` and `exitFor`, never a
list restated in the test — and reads the README as the rendered assertion being checked. Add a
state and it fails until the front door says so; change an exit code and it fails until the table
agrees.

**Red established against `main` itself, not against the old branch.** Run before any correction, on
`3eeb65b`, three of its four tests failed and the first named all five phantom states by name:

```text
✖ front door · the README documents exactly the states the code has
    the README lists states scripts/states.mjs does not define: COMPLIANT,
    COMPLIANT_WITH_EXCEPTIONS, NON_COMPLIANT, NOT_EVALUATED, BLOCKED_BY_INVARIANT
✖ front door · every documented exit code is the one exitFor produces
    COMPLIANT is documented as exit 0, but exitFor returns 4
✖ front door · the projection is the three codes the exit contract defines
    the README does not show the exit-code projection anywhere
```

The paragraph was correct once. What was missing is anything that notices when it stops being — the
same shape as [ST-10](ST-10.md) for the backlog tracker and [ST-08](ST-08.md) for symlink capability,
applied to prose.

## Note

Finding 6's fix was to **change the statement, not create the directory.** "Intentionally empty"
asserted a filesystem state that did not exist, and the honest correction is that the directory is
absent and `planning.breakdown-directory` fails on purpose. Creating it — even empty — to make the
sentence true would have been satisfying a rule dishonestly, which is the thing the sentence was
trying to refuse in the first place. Re-verified absent on `main`, 2026-08-16.

**This does not close [EP-04](EP-04.md).** The epic now has two complete children rather than one,
and that is arithmetic. Whether release and authority reconciliation is *done* is a separate
disposition — and this item is evidence for it, since that reconciliation was not complete while the
public front door still advertised the superseded state contract.
