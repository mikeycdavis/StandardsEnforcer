## What

Every assurance surface in this repository's enumerated test surface must prove, at execution time,
that it looked at something before its success can be accepted.

> **Acceptance property.** Any assurance test that derives a verdict from a collection must prove at
> execution time that the collection is non-empty before a success verdict can be accepted.

Today that is a convention. This story makes it a mechanism.

## Why

[EP-06](EP-06.md)'s seven children are all complete, and the epic's own failure is still reachable on
`main@d8ca361`. Demonstrated, not argued — one file added to the surface:

```js
test("probe · no source file contains a forbidden marker", async () => {
  const files = [];                  // populated by nothing
  const offenders = [];
  for (const f of files) { /* never runs */ }
  assert.deepEqual(offenders, []);   // vacuously true, forever
});
```

```
385 tests, 355 pass, 0 fail, 30 skipped   <- the probe passed, and nothing objected
```

[ST-13](ST-13.md)'s enumeration picked the probe up and added it to the authoritative surface. That
is the mechanism working exactly as designed, and it is what makes the result damning: the
repository certified a guard that examined nothing, and counted it toward its own assurance.

**The gap is between a pattern and a mechanism.** The word `liveness` appears in three places on
`main`: one comment in `test-support/source-scan.mjs` stating that every caller asserts its own, and
two callers that actually do — `test/adapter-policy-binding.test.mjs:259` and
`test/oracle-subject-identity.test.mjs:107`. A convention documented in prose, honoured by two
files, enforced by nothing.

The completed children establish that seven named holes are shut. They do not establish that an
eighth cannot be opened by the next commit. That difference is this story.

## Acceptance

Red-first, in this order. Each step must be evidenced by execution, not by reading.

1. **The falsifier exists first.** Add a newly enumerated test whose subject is empty and whose
   assertion passes — the probe above, or one of the same shape.
2. **Prove the current suite accepts it.** The probe must be shown green, inside the authoritative
   surface, against the base this work starts from. A falsifier that was never observed passing has
   not established the defect.
3. **Implement an executable mechanism over the authoritative test surface** that makes that probe
   red. Its subject is `testFiles(ROOT)` — the other checks — not any one suite.
4. **Prove legitimate existing assurance tests remain green.** The full surface must pass with the
   mechanism in place. A mechanism that reddens honest guards has replaced one false verdict with
   another.
5. The mechanism's own liveness is asserted, as [ST-11](ST-11.md) requires of any structural guard:
   it must be shown to fire on a planted violation and to stay silent on the remedy, or it is
   indistinguishable from a broken matcher.

## Explicitly not a solution

Ruled out by the property, not by preference. Each of these can be fully satisfied while the probe
above still passes:

- **Test counts.** A count rises when the vacuous guard is added.
- **Coverage thresholds.** The probe executes every line it contains.
- **Naming conventions.** A rule about identifiers is not a statement about what executed.
- **Prose rules.** That is the present state, and the present state is what this story exists to
  replace.

## Notes

**Scope.** The subject is this repository's own assurance surface, per EP-06's boundary. It is not
a guarantee offered to governed repositories, and it must not become a place to file findings merely
because a test was involved.

**This is categorically unlike EP-06's other children.** All seven were repairs of a located
instance. This is a check whose subject is the other checks, which is why it is filed as its own
story rather than as an amendment to a closed one.

**Do not close EP-06 when this closes.** The parent guarantee is evaluated separately, at the parent
level, as it was on 2026-08-27 when a full child count did not establish it.

**The hard part is the discriminator, not the enforcement.** "Derives a verdict from a collection"
must be recognisable mechanically without reddening honest guards, and a scan that cannot tell those
apart will fail step 4. Expect the discriminator to need its own falsifier before the mechanism does.

## Outcome

Closed 2026-08-28 on [#41](https://github.com/mikeycdavis/StandardsEnforcer/pull/41) (`fefecd1`,
merged as `50b360d`). Each acceptance step is closed on an execution, not on a reading.

**1–2 · The falsifier passed first.** The probe was added to the enumerated surface on
`main@f035ab9` and observed green: `385 tests, 355 pass, 0 fail, 30 skipped`. Nothing objected. The
defect is established by that run, not by the argument above it.

**3 · The discriminator was falsified before the mechanism was written**, and running it against all
35 surface files found three defects in it:

| Draft | What running it revealed |
| --- | --- |
| 1 | Flagged `test/scope.test.mjs` for `deepEqual(f.kinds, [])` — a field of one result object, not a collection that could have been vacuously empty |
| 2 | Accepted liveness only as `> 0`, so it flagged `test/diagram-sync.test.mjs`, which asserts `SOURCES.length >= 2`. A higher bound is a stronger liveness claim, not a weaker one |
| 3 | Read the bound's number without its operator, rejecting `assert.ok(files.length > 0)` — and so flagged the very guard whose liveness [ST-11](ST-11.md) introduced |

Final state: one file flagged across 35 — the specimen — and 34 legitimate guards untouched, which
is acceptance criterion 4 measured rather than asserted.

**5 · The mechanism's own liveness.** Stripping `test/verdict-liveness.test.mjs` of its liveness
assertions initially did **not** make it flag itself: its specimens are held as string data, and
`stripComments` removed commentary but not string bodies, so a file could have satisfied the rule
with data instead of code. Repaired at the shared helper — `stripComments(source, { strings: true })`,
defaulting to `false`, leaving all ten `source-scan` tests unchanged — rather than by duplicating its
state machine, which is the duplication [ST-12](ST-12.md) recorded. With the repair, the planted
violation makes the mechanism name itself alongside the specimen.

**Verification.** Local `390 tests / 360 pass / 0 fail / 30 skipped` — 22 oracle-dependent, 4
symlink, 4 unreadable-file (the platform ignores `0o000`, recorded NOT simulated rather than passed);
unchanged by this work. Hosted run
[33196422550](https://github.com/mikeycdavis/StandardsEnforcer/actions/runs/33196422550) on
`fefecd1`: a real runner, Node 20, `credential-hygiene: ESTABLISHED`, `390 / 389 / 0 / 1`, zero
`not ok`, the sole skip being the win32-only drive-letter case `5b`, and all six `liveness ·` tests
executed.

The specimen lives at `test/fixtures/liveness/vacuous-guard.specimen.mjs` — outside the enumerated
surface, so it stays re-runnable without reddening the suite permanently, and the mechanism scans it
as a real file rather than only as a string.

**Observation, not work.** While regenerating the tracker for this closure the generated table was
corrupted and had to be restored from git: `backlog.mjs --print` emits `…` placeholders for
description columns, and a keyed line replacement overwrote real prose and a table header. The
checker still passed, because it reads only the count column. A validator agreeing is not the
document being correct. Recorded here as an observation; no item is opened for it.

**EP-06 is not closed by this.** The parent guarantee is evaluated separately, at the parent level.
