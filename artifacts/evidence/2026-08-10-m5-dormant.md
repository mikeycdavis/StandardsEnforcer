# M5 is dormant, not failed

**Date:** 2026-08-10 · **Applies to:** [the M5 protocol](2026-08-10-m5-protocol.md) at `c29e73c` ·
**Status:** frozen, unexecuted, reopenable

The protocol is **not amended**. It records hypotheses and expected outcomes written before the
experimental environment existed, and that ordering is the only thing that makes it evidence rather
than a description of whatever GitHub turned out to permit. Editing it now — even to note that it did
not run — would spend that property for nothing. This record sits beside it instead.

## What happened

Nothing. M5 requires a GitHub organisation, an organisation cannot be created through any API on
github.com, and creating one was judged not to be warranted by the current evidence. The experiment
was not attempted.

That is a decision about infrastructure, not a result about enforcement.

## The distinction being preserved

```text
M5 failed                 the organisation root was tested and did not hold
M5 is dormant             the organisation root has not been tested
```

Only the second is true. Recording it as the first would manufacture a negative result, which is the
same category of error as manufacturing a positive one — an unknown reported as an answer. The
architecture's central invariant is that an unknown never resolves in the convenient direction, and
"convenient" here includes *pessimistic*, because a false negative would justify abandoning a root
that may well work.

## Position, unchanged from M4

| | |
| --- | --- |
| Latest completed enforcement experiment | **M4** |
| Repository-level GitHub Actions enforcement | **proven insufficient**, live |
| Organisation required-workflow rules | **candidate remediation, not live validated** |
| Live-validated authoritative GitHub root for Actions | **none** |

## Reopening condition

> An organisation-level GitHub test environment becomes available that does not require creating or
> paying for infrastructure the owner does not otherwise want.

When one does, the protocol at `c29e73c` runs unchanged, including its two stop conditions: a failed
case 5.1 halts the run, because a remedy that fails in the honest case removes the control that makes
case 5.2 interpretable; and an inability to instantiate the precommitted two-rule configuration is
itself a result, not licence to redesign the experiment mid-run.

## What must not be substituted

**A new personal-repository experiment is not M5.** M4 already established what a personal repository
can show, and repeating it under a different name would convert an untested hypothesis into an
apparently tested one by relabelling.

If an external GitHub App — or any other root suitable for personal and private repositories — is
investigated later, it is a **different hypothesis and needs its own protocol**, written before its
environment exists, exactly as this one was. It would be answering a question M5 does not ask: not
*can an organisation root hold*, but *is there a root available to a repository with no organisation
at all*.
