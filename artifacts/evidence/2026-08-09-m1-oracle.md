# M1 oracle — one release, one repository, no second evaluator

**Date:** 2026-08-09 · **Enforcer:** `0.1.0` · **Standards under test:** MachineLearningStandards
`v1.4.0` at `6bfd0789e50196da3ff666594ff5b981b8ae5763`, tagged and unmodified.

The claim being tested is not "can StandardsEnforcer run MachineLearningStandards". It is whether,
given the same target and the same release, it reproduces the official result **without inventing
another route to it**.

## Payload fidelity — the half of the claim that matters

The official CLI is run directly out of the verified checkout, then the same target is run through
the enforcer, and the two reports are compared field by field. Anything the enforcer computed for
itself would appear here as a difference.

```text
status               equal
score                equal
schemaVersion        equal
standardVersion      equal
results[]            deep equal
summary              deep equal
frameworkCoverage    deep equal
standards exit code  equal, and carried through
```

Asserted for both a compliant and a non-compliant target, so the equality is not an artefact of an
empty result set.

## Identity

```text
tag v1.4.0 resolves to 6bfd0789e50196da3ff666594ff5b981b8ae5763, and the declared identity
says 0000000000000000000000000000000000000000
```

The report names both, because "the tag does not match" and "the tag points somewhere you did not
expect" lead to different actions. An abbreviated SHA is refused outright: an abbreviation is not an
identity.

The checkout cache is content-addressed —
`…/standards-enforcer-cache/6bfd0789e50196da3ff666594ff5b981b8ae5763` — so an entry cannot be stale,
because its name is what it contains. A partially built entry is removed and rebuilt rather than
reused, since a truncated checkout would run a subset of the implementation and report a verdict
from it.

## A defect the structural guard caught on its first run

The test asserting the enforcer contains no rule, detector or scoring of its own failed immediately.
The one-line summary read:

```js
report.status === "BLOCKED_BY_INVARIANT" || report.score === null ? "not computed" : `${report.score}%`
```

That restates the MachineLearningStandards rule *blocked means unscored* — v1.1's third remediation —
in a place where it would go stale the moment that rule changed. Reading `report.score` and saying
what is there needs no opinion about why it is null. Fixed by removing the re-derivation, not by
relaxing the guard.

The guard's pattern then produced one false positive of its own, matching `report.score === null` as
though it were an assignment. Tightened to `score\s*=(?!=)` — a comparison reads what the standards
produced, which is the entire point of this repository; an assignment would mean it computed one.

## What this does not establish

- **Nothing about repositories that never adopted.** `NOT_ADOPTED` is reported, and the enforcer
  cannot yet say whether that repository was obliged to adopt. Until it can, this system enforces an
  opt-in.
- **Nothing about a removed gate.** `GATE_MISSING` is in the vocabulary and unreachable.
- **Nothing about composition.** One standards system, one target.
- **Nothing the standards system itself cannot establish.** Ten of forty-five MachineLearningStandards
  rules are machine-examined; the enforcer inherits that boundary exactly and does not narrow it.

16 tests, all passing. Where MachineLearningStandards is absent from disk the identity and oracle
tests skip loudly rather than passing quietly — a suite that goes green when its subject is missing
is the failure this family of repositories exists to prevent.
